# money-home — Product Spec

PWA для учёта расходов и доходов по счетам, с планированием покупок.

Читать **только нужную секцию**. Не расширять код и UI за пределы текущего запроса и Non-Goals.

## Goal

Пользователь ведёт личные счета: расходы и доходы по категориям, переводы, авто-пополнения и регулярные расходы. Счёт можно расшарить кодом — тогда данные этого счёта общие. Перед запланированной покупкой система считает, хватит ли денег на выбранном счёте к дате; если нет — предлагает более позднюю дату или перевод. «Готово» по покупке списывает сумму и создаёт расход.

## Users & Access

- Auth: email + password (Supabase Auth). Сброс пароля письмом и смена пароля в профиле.
- После входа — сразу приложение. Household как «одна семья на всё» нет.
- Один пользователь — много счетов. При регистрации создаётся пустой счёт. Создать свой или присоединиться по коду.
- Члены одного счёта видят и редактируют наравне (роли v1 не различаем). Owner — создатель; leave может не-owner. Owner без других участников может удалить счёт; с участниками передаёт права самому «старому» члену и уходит.

## Stack

Vue 3, Vite, TypeScript, Pinia, Vue Router, PWA (`vite-plugin-pwa`). FSD: `app`, `pages`, `widgets`, `features`, `entities`, `shared`. Backend: Supabase (Auth, Postgres, RLS, Realtime). Валюта: RUB. UI: русский.

Секреты (`service_role`) только на сервере/в CI; в клиенте — `VITE_SUPABASE_URL` + `VITE_SUPABASE_ANON_KEY`.

## Domain Model

### Profile

`user_id`, `display_name`, `preferences` (json; нижнее меню, порядок разделов и счета в сайдбаре; по умолчанию предложения при вводе суммы включены).

### Account

`id`, `name`, `amount` (баланс, RUB), `owner_id`, `invite_code` (nullable unique; появляется при шаринге), `exclude_from_total`, timestamps. Создатель сразу член и owner.

### AccountMember

`(account_id, user_id)`.

### CategoryGroup

Папка для группировки категорий и цветовой семьи, не цель проводки. Один уровень, без вложенности.

- `kind`: `expense` | `income`. `name`, `color` (базовый цвет семьи), `sort_order`, `created_by`. Без иконки: в списке группа — папка с цветовой меткой, не строка категории.
- Привязка ко счетам: `category_group_accounts` (M2M), как у категорий. При создании группы — все текущие счета пользователя. На общем счёте группа общая, правят все члены.
- Unlink с одного счёта не удаляет с других; unlink с последнего — удаляет группу.

### Category

- `kind`: `expense` | `income`. `name`, `color`, `icon` (ключ из набора SVG), `created_by`, `sort_order`.
- `group_id` nullable → `category_groups`. `color_manual` (по умолчанию false).
- `kind` ребёнка = `kind` группы. Операции, покупки, правила, избранное — только на категорию (лист). `category_id` нигде не указывает на группу.
- Без группы: привязка ко счетам `category_accounts` (M2M). При создании категории — все текущие счета пользователя.
- С группой: видимость по счетам наследуется от группы; свои строки в `category_accounts` не используются.
- При создании/редактировании счёта — чеклист групп (одна галка = вся группа) и категорий без группы. Детей группы по отдельности не показывают.
- На общем счёте привязанные категории общие. Unlink с одного счёта не удаляет с других; unlink с последнего — удаляет категорию. Правка имени/цвета/иконки одна на сущность.

### Transaction

Posted-операция:

- `kind`: `expense` | `income` | `transfer`
- `account_id`; для перевода ещё `counterparty_account_id`
- `category_id` (nullable), снимки `category_name`, `category_color`, `category_icon`
- `amount` (> 0), `occurred_on`, `title?`, `notes?`
- `status`: `posted` | `cancelled`
- `source`: `manual` | `income_rule` | `expense_rule` | `transfer_rule` | `purchase`
- `created_by`

Расход уменьшает баланс, доход увеличивает, перевод — атомарно оба счёта. В истории — `posted`.

### Purchase

План (не posted, пока не «Готово»): `title`, `amount`, optional `planned_date`, `notes?`, `account_id`, `category_id`, снимки категории. `status`: `planned` | `done` | `cancelled`. В проекции только `planned` с датой. Без даты — бэклог, в баланс не входит. Дата сама не списывает; просроченные визуально выделены. «Готово» → расход (`source=purchase`) + списание.

### IncomeRule / ExpenseRule / TransferRule

Регулярное авто-пополнение / авто-расход / авто-перевод. Фактическая проводка в календарный день.

- Income/expense: `account_id`, optional `category_id` нужного kind
- Transfer: `from_account_id`, `to_account_id` (разные; член обоих), без категории
- Общее: `amount` (> 0), `title?`, `active`
- `frequency`: `weekly` | `biweekly` | `monthly`
- `weekly` / `biweekly`: `weekday` (0=вс … 6=сб); `monthly`: `month_day` 1–28; `biweekly`: `anchor_date`

### IncomeOccurrence / ExpenseOccurrence / TransferOccurrence

Уникально `(rule_id, occurred_on)`. `status`: `posted` | `skipped` | `adjusted`. `transaction_id?`. Не переначислять/пересписывать skipped; миграция старых правил задним числом не доначисляет.

### SavingsGoal

Виртуальная копилка на счёте (несколько на счёт). Не проводка и не резерв: не меняет баланс, «свободно до пополнения» и `canAfford`.

`account_id`, `title`, `target_amount` (> 0), `target_date`, `saved_amount` (≥ 0, сколько отмечено накопленным), `started_on`, `status`: `active` | `completed` | `cancelled`, `created_by`. «Уже отложено» / правка накопленного — только метка, не доход и не перевод. Сумма `saved` по активным целям может быть больше баланса — предупреждение, без блокировки.

Совет «дополнительно вносить X ₽ в месяц»: в первую очередь факт за наблюдаемый срок до 90 дней (все posted: ручные, авто-правила, покупки, переводы счёта); пустые дни до первой операции не считаются, меньше месяца — как один месяц. Будущие правила дохода/расхода — только если истории нет. Плановые покупки вычитаются всегда. Жадное покрытие remaining по возрастанию даты.

### Activity (in-app)

`kind`: `purchase_created` | `purchase_updated` | `purchase_done` | `purchase_cancelled` | `account_updated` | `income_rule_changed` | `expense_rule_changed` | `transfer_rule_changed` | `transaction_created` | `income_auto_posted` | `expense_auto_posted` | `transfer_auto_posted` | `savings_goal_changed`.

Свои действия в ленту не попадают, **кроме** `income_auto_posted`, `expense_auto_posted` и `transfer_auto_posted` (всем членам, включая того, кто открыл приложение). `transaction_id` / `purchase_id` / `savings_goal_id` optional.

## Auto income & expense

Правило задаёт календарный день, не час. Проводка за день D — когда наступает D.

- RPC `apply_due_income_rules(p_as_of date)` / `apply_due_expense_rules(p_as_of date)` / `apply_due_transfer_rules(p_as_of date)`: даты `starts_on <= d <= p_as_of` по active rules, без существующего occurrence. Unique + `on conflict do nothing`.
- Доход зачисляет, расход списывает, перевод атомарно оба счёта (`kind=transfer`, `source=transfer_rule`). Клиент вызывает все при bootstrap (локальная дата). Catch-up пропущенных дней.
- Уведомление в ленте. **Отменить** — сторно, status `skipped`. **Изменить** — новая сумма > 0, status `adjusted`.

## Balance Projection Algorithm

Чистая функция (без I/O) **по одному счёту**.

### Inputs

- `currentBalance` этого счёта
- `asOfDate`, `targetDate` (`targetDate >= asOfDate`)
- `incomeRules` / `expenseRules` — active правила **этого** счёта
- входящие / исходящие `transferRules` этого счёта (получатель как пополнение, источник как расход)
- `postedOccurrenceDates` / `postedExpenseOccurrenceDates` / даты transfer occurrence — даты с occurrence (posted/skipped/adjusted) — в прогноз не входят
- `plannedPurchases` — `planned` **этого** счёта
- `candidateAmount`, `excludePurchaseId?`

### Rules

1. Стартовый баланс = `currentBalance` (уже включает прошедшие авто-пополнения, авто-расходы и авто-переводы).
2. Пополнения: даты `d` где `asOfDate < d <= targetDate`, нет occurrence, суммировать `amount`. Входящие регулярные переводы — как пополнения.
3. Регулярные расходы: тот же интервал, нет occurrence, суммировать `amount`. Исходящие регулярные переводы — как расходы.
4. Планы: `planned` с `asOfDate < planned_date <= targetDate` (покупки на `asOfDate` не вычитаются).
5. `projectedBalance = currentBalance + incomes + incomingTransfers - plannedSpend - expenseRuleSpend - outgoingTransfers`.
6. `canAfford = projectedBalance >= candidateAmount`.

### Outputs

`projectedBalance`, `canAfford`, `shortfall`, `plannedBeforeTarget`, `incomeTotal`, `incomeOccurrencesCount`, `nextAffordableDate` (горизонт 365 дней), `message`.

При отказе: счета пользователя, у которых `available` (баланс − planned до target, без чужих счетов) ≥ `shortfall` — CTA «Перевести `shortfall` ₽». После перевода — повторная проекция и сохранение покупки.

### Available until next income

По карточке счёта: ближайшая **будущая** дата пополнения без occurrence (включая входящий регулярный перевод); из баланса вычитать `planned` с датой строго раньше этой даты (включая сегодня и просроченные) и будущие регулярные расходы и исходящие переводы строго до этой даты.

Для всех счетов без `exclude_from_total`: та же формула до **одной** ближайшей даты пополнения среди этих счетов; регулярные переводы между ними не входят ни в дату, ни в резерв.

### Example (acceptance)

На счёте к 25 августа с учётом будущих пополнений и планов будет 1500 ₽. Покупка: «штора», 2300 ₽, 25 августа. Ожидание: отказ; если на другом счёте свободно ≥ 800 ₽ — CTA «Перевести 800 ₽ со счёта …».

## Product surface (v1)

Контракт экранов и поведения. Это не бэклог: не реализовывать соседние пункты «заодно».

**Auth.** Регистрация / вход email+password; сброс письмом; смена пароля в профиле; выход с подтверждением. Без сессии → login; с сессией → главная. При регистрации создаётся пустой счёт «Основной счёт». Если каталог категорий пустой, клиент при первой загрузке добавляет стартовый набор групп и категорий. После первого входа — гайд по экранам (шаг можно пропустить); повтор из «Настройки».

**Accounts.** При регистрации — пустой «Основной счёт». Создать ещё (имя, стартовый баланс, чеклист категорий). Поделиться кодом; присоединиться по коду (тот же счёт, не копия); покинуть (не owner). Owner без участников удаляет счёт вместе с операциями и правилами; с участниками — передаёт владельца самому «старому» члену и уходит. Список на отдельной странице: до трёх счетов в боковом меню; порядок выбранных — режим перемещения у «Счета» в меню; в меню — выбранные и «Все счета». На карточке — «свободно до пополнения». Правка имени/баланса; не учитывать в общем балансе; привязать категории. Перевод между своими счетами (член обоих). На карточке счёта — «Копить»: название, сумма, дата, необязательно «уже отложено»; живой совет, сколько ещё вносить в месяц. Список копилок с прогрессом и вердиктом «укладываемся» / «не укладываемся»; правка, завершение, удаление в нижнем дровере. Если не укладываемся — ссылка «Как накопить»: онлайн, агрегаты трат по категориям за 30 дней vs предыдущие 30 без названий операций, советы нейросети в нижнем дровере. Отдельная страница «Копилки» в меню: фильтр счёта в шапке, группировка по счетам, кнопка «Копить».

**Categories.** CRUD группы и категории (дроверы). Список разделён на расходы и доходы; секции-папки по группам, внизу «Без группы». Группа: имя, цвет семьи, kind, счета (дефолт все); иконки нет. Категории перетаскивают между группами и в «Без группы». Смена цвета группы перекрашивает детей в ту же семью (тот же индекс оттенка). Категория: имя, цвет, иконка, kind, группа или «без группы»; счета — только если группы нет. Удаление группы распускает её: дети остаются, `group_id` сбрасывается, счета группы копируются детям; история операций не меняется. На общем счёте все члены видят и правят. В расход/доход/покупку/правило — только категории (листы) выбранного счёта и нужного kind; в пикере секции по группам, пустую группу выбрать нельзя. Стартовый набор: при пустом каталоге создаётся сам; если категории уже есть — на странице можно добавить недостающие (совпадение имени и kind пропускается, структура не меняется). После применения повторно не засеивается.

**Expenses & income.** Расход/доход: счёт, категория, сумма, дата, optional title/notes → сразу проводка. В форме и из карточки операции можно выделить часть суммы в другие категории того же счёта; остаток в выбранной категории; одно сохранение — отдельные posted-операции; не для переводов и авто-правил. Если на главной выбран счёт — он в форме. В дровере поле «Что записать»: онлайн разбор строки в сумму, категорию этого счёта, название и дату (сегодня/вчера/позавчера); без сети — только локальный разбор суммы/даты/имени категории. Подстановка не сохраняет операцию — «Сохранить» как обычно. Если сумма и категория из списка уже ясны, модель не вызывается; иначе неуверенный разбор — карточка «Подставить». При вводе суммы — до 3 совпадений среди posted того же kind (сначала текущий счёт; категория должна быть у текущего счёта); выбор заполняет категорию, название, комментарий; счёт и дата без изменений; только если включено в персонализации. Избранные шаблоны (личные): сумма, категория, название, комментарий; CRUD на «Избранное»; в форме — кнопка списка; выбор подставляет поля, кроме счёта и даты; если категории нет у текущего счёта — она не меняется. Повторы за последний год (posted, `manual`, ≥3 разные даты, тот же счёт/сумма/категория): после сохранения и баннером на главной предложить правило — один день недели (шаг 7/14) или день месяца 1–28; иначе избранное. «Добавить» открывает форму правила с предзаполнением или сразу создаёт шаблон; «Не сейчас» скрывает этот шаблон. Из карточки операции в истории можно добавить избранное или открыть форму правила с предзаполнением (кроме переводов). История: период день / неделя / месяц / год / все время / произвольный; мультифильтр типа; сумма за период и за день.

**Income & expense rules.** CRUD на конкретном счёте; optional категория нужного kind. Только active проводятся и входят в проекцию. Catch-up при входе; уведомление; отмена / правка начисления. Форму нового правила можно открыть с предзаполнением из операции в истории или из повторяющихся операций (кроме переводов). Регулярный перевод: два своих счёта, сумма, расписание, optional название. Управление — фильтр «Регулярные» на странице «Планы»: лента по ближайшей дате, на карточке метка типа, toggle и удаление; выключенные внизу. Создание — «Добавить» (пополнение / расход / перевод); из месяца — с датой выбранного дня.

**Plans.** Страница «Планы». Фильтр Все / Покупки / Регулярные; список и месяц; фильтр счёта в шапке. Одна лента для всех фильтров. «Все» — `planned`-покупки и ближайшие даты active-правил, на карточке метка типа; просроченные сверху; без даты — «На будущее». Покупки: поиск и фильтр категории. Свайп «Готово» без confirm; меню — с confirm, правка и отмена. Правила: toggle, меню изменить/удалить. «Добавить» всегда: покупка / пополнение / расход / перевод. Вид месяца: сетка с покупками и правилами; из дня — то же «Добавить» с датой дня. Создание/редактирование planned через проекцию, если есть дата (edit exclude себя); без даты проекция не считается. «Готово» → расход + списание; отмена → `cancelled`.

**Home chart.** Кольцевой график по категориям (расходы/доходы); по клику — доля. Обзор: группы (сумма детей, цвет группы) + категории без группы + «Без категории». Тап по группе — drill только детей этой группы за тот же период; назад к обзору. Тап по листу или «Без категории» — история с фильтром. Rollup по текущему `group_id` (линза, не снимок). Период: день / неделя / месяц / год / произвольный. Фильтр по счёту в шапке, включая «все счета». Лента ближайших 7 дней: просроченные и будущие планы, даты правил; клик открывает «Планы» со списком и этим пунктом.

**Statistics.** Расходы и доходы за период; фильтр счёта и периода; один график, выбор вида: кольцевой по категориям, столбцы по дням недели, тепловая карта, динамика, топ операций, по счетам (если «все счета»), по участникам на общем счёте (ручные операции и покупки, без авто-правил), прогноз баланса на 30/90 дней. Вид «по категориям»: тот же rollup и drill, что на главной. Сравнение с прошлым периодом, средний расход в день и доля расходов от доходов — в дровере по кнопке «Сводка и советы» в начале страницы для любого вида графика. В том же дровере — онлайн разбор периода к прошлому аналогу: агрегаты по группам и категориям без названий операций и без имён участников; 1–3 шага с CTA в историю группы/категории, операцию или прогноз. Период «все время» или нет прошлого интервала — без плашки, кроме ухода прогноза в минус. Офлайн плашка скрыта.

**Settings.** Сайдбар: до трёх выбранных счетов (кнопка режима перемещения у «Счета») и «Все счета»; разделы в заданном порядке (кнопка режима перемещения у «Разделы»); настройки. Настройки: тема; подсказки; ссылки на профиль и персонализацию. Профиль: имя; email; смена пароля; выход. Персонализация: предложения при вводе суммы; состав нижнего меню (ровно 4 пункта, слоты 1–4); на профиле, синк между устройствами, last-write-wins; по умолчанию предложения включены, нижнее меню — Главная · Статистика · Планы · Перевод.

**PWA & shell.** Installable PWA; sticky nav + safe-area; шапка + лента Activity. После хотя бы одного успешного входа открывается без сети (локальная копия). Офлайн: смотреть и делать обычные записи (расход, доход, перевод, покупка, «Готово», правки, категории, правила, копилки, имя/баланс счёта) — очередь, синк при сети. После синка источник истины — сервер; на общих счетах без ручного merge: append-only операции складываются, правки одной сущности — last-write-wins, «Готово» не откатывается, непринятая мутация сбрасывается очередью. Только онлайн: вход, регистрация, смена/сброс пароля, присоединиться, поделиться, покинуть, удалить счёт, советы «Как накопить», разбор строки расхода/дохода, разбор статистики. Истёкший JWT без сети не выкидывает на логин. В шапке: «нет сети» / «синхронизация» / ошибка синка с повтором; несинкнутые строки отмечены.

**A11y.** `:focus-visible`; focus trap в дроверах; `role="alert"`; toast; hit target ≥ 44px.

## Non-Goals (v1)

- Мультивалютность, кредиты, бюджеты, банковские интеграции
- Разрезы статистики: траты в день зарплаты
- Типы счетов (карта/нал)
- Произвольные картинки иконок (только набор SVG)
- Начисление в конкретный час
- Несколько независимых «семей» как сущность; шаринг только счёт
- Роли внутри счёта
- Push; продуктовые email (Auth-письма восстановления пароля — да)
- Откат done-покупки; редактирование done/cancelled покупок
- Удаление owner-счёта с участниками (leave + invalidate code)
- Сложный UI-kit / wide desktop-layout

## Supabase

- Таблицы: `profiles` (`preferences` jsonb), `accounts`, `account_members`, `categories`, `category_accounts`, `category_groups`, `category_group_accounts`, `transactions`, `income_occurrences`, `expense_occurrences`, `transfer_occurrences`; `income_rules`, `expense_rules`, `transfer_rules` (`from_account_id` / `to_account_id`), `purchases` и `savings_goals` с `account_id`; `operation_templates` (личные шаблоны расхода/дохода).
- RLS: данные счёта iff член; категория видна/редактируема, если член хотя бы одного привязанного счёта (для категории в группе — счетов группы); группа — если член хотя бы одного её счёта.
- Join счёта — RPC по коду. Realtime по счетам пользователя.
- RPC авто-пополнений, авто-расходов и авто-переводов идемпотентны.
